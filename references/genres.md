# 题材写作模版

`$SK` = 本 skill 的 `scripts/` 目录，`$A` = `assets/` 目录。

本 skill 自带 **37 个题材的写作模版**（男频 19 + 女频 18），用户不需要自己建参考语料库——评分维度和写作细则已经从几百本高分作品里反推出来固化在里面了。

```
$A/templates/INDEX.md          全部题材一览 + 成熟度分级
$A/templates/<男频|女频>/<题材>.md   给人读的：套路、开局钩子、立项问题、质量自检表
$A/prompts/_universal_craft.txt     所有题材共享的通用手艺（31 条，始终生效）
$A/prompts/<男频|女频>/<题材>.txt    给模型读的：该题材专属的规则层
```

## 通用手艺层

`_universal_craft.txt` 里是 31 条与题材无关的手艺——段落怎么切、句长怎么混、对话怎么断、信息怎么释放、人物怎么立、章节之间怎么换色，以及三条禁止项（不许把写作技巧标签写进正文）。**与 `--genre` 无关，始终加载**。

它的来历值得知道：这批规则原本全在西方奇幻的题材层里。那个题材的规则层曾有 4894 字，而另外六个 A 级题材只有 899–1138 字——逐条审计后发现，那 4894 字里 **81% 与题材无关**，只有 489 字是真正题材相关的（金手指/系统的呈现方式）。所以把通用的部分提上来给所有题材共享，37 个题材的规则密度就此拉平：实测进提示词的总量都在 5100–5500 token。

`build_templates.py` 重建题材层时会自动跳过这 31 条，不会重复喂两遍。要改通用手艺就直接编辑这个文件；要给单个题材补规则还是走 `.author.txt`。

## 怎么用

写作时加 `--genre`：

```bash
python3 $SK/write_novel.py write --project "<书名>" --genre 西方奇幻
python3 $SK/write_novel.py write --project "<书名>" --genre 女频/悬疑脑洞    # 男女频同名时要指明
python3 $SK/write_novel.py write --project "<书名>" --genre ./我的规则.txt   # 也接受文件路径
```

它是**追加**在默认写作规范之后，不是替换——通用的段落、节奏、对话、章末悬念规则仍然生效，题材层只补这个品类特有的东西。（`--system-prompt` 才是整套替换，两者可以同时用：先替换底座，再追加题材层。）

题材名写错会列出全部 37 个可用名字，不会静默跑错。

**立项阶段也要用**：和用户聊设定之前，先读 `$A/templates/<性别>/<题材>.md`，用里面的"读者预期与核心套路"和"立项时必须定下来的"去提问。这比自由发挥地问"你想写什么"有效得多。

## 成熟度分级

模版标了 A/B/C 三级，是对"这套规则有多少证据支撑"的诚实标注：

| 级别 | 含义 | 数量 |
|---|---|---|
| **A** | 写作细则经过多轮"生成→评审打分→改写提示词"迭代，按评审分挑出最优那轮 | 7 个 |
| **B** | 有从该题材高分作品反推的 10 项评分维度（含判分标准），规则层由维度转写而成 | 30 个 |
| **C** | 只有套路库和开局钩子 | 0 个 |

A 级：东方仙侠、传统玄幻、动漫衍生、历史古代、西方奇幻（男频），玄幻言情、古言脑洞（女频）。评审分 7.2–8.4 分（10 分制），分数来自和真实高分作品对标的评审模型，仅供相对比较，不要当成绝对质量承诺。

B 级也完全能直接写——10 项带权重的评分维度本身就是很具体的写作指令，而通用写作规范已经覆盖了基本功。想把某个题材从 B 升到 A，见 `corpus.md`。

## 作者自己写的规则：`.author.txt`

用户想加自己的规则（这本书的专属忌讳、特定文风、编辑给的要求），**不要直接改生成出来的 `<题材>.txt`**——重建模版时会被覆盖。放这里：

```
$A/prompts/<性别>/<题材>.author.txt
```

`--genre` 会把它自动接在题材层后面，而 `build_templates.py` 永远不碰它。后写的规则在提示词里位置更靠后，和前面冲突时通常以它为准。

适合放进 `.author.txt` 的东西：
- 这个题材里用户不想要的套路（"不写系统流"、"不要后宫"）
- 平台的内容要求（某些平台对暴力、情色、政治描写的红线）
- 用户自己总结出的爽点节奏（"每三章一个小高潮，每十章一次大反转"）

给单本书的规则也可以直接写成一个 txt 文件，用 `--genre ./这本书的规则.txt` 传进去。

## AI 味词表：`ai_cliches.author.txt`

套话词表和题材规则是两套东西，改的地方也不同：

```
$A/ai_cliches.txt          # 跨题材通用的，随 skill 分发
$A/ai_cliches.author.txt   # 自己的补充，不会被任何重建覆盖
```

格式一样：`[分类] 这一类的修法`，然后每行一条；行首 `!` 表示铁套话（叙述里出现一次就报），
不带前缀的按密度报。分类后面那句修法会直接显示在诊断报告里，所以写成**能照着做的动作**，
不要写"避免使用"。

两份文件都会被读进来，所以 `.author.txt` 里只写要补的，不用抄一遍原表。

**什么该写进这里，什么该写进 `.author.txt` 的题材规则**：套话是"这个词组本身就是偷懒"，
跨题材都成立，写进词表；"这个题材不要写系统流"是题材偏好，写进题材规则。如果某个套话
只在一个题材里算毛病（比如仙侠里的"道心"在都市文里根本不会出现），写进词表也无害——
它在别的题材里本来就不会命中。

## 重建模版

```bash
python3 $SK/build_templates.py --repo <语料库项目目录>
```

从 `review_loop/` 的迭代产出 + 套路库重新生成全部 37 个模版。两个开关值得知道：

- `--quotes strip`（默认）：评分维度里有些示例直接引用了真实商业小说的原文片段。默认只保留判分标准、剥掉引文——**要分发给别人的版本必须用这个**。
- `--quotes keep`：保留引文，自己本机参考时更直观，但不要把这样生成的 assets 发出去。

中文套路库在 `$A/category_zh.json`，可以直接编辑（改完重建生效）；缺失的题材会回落到生成脚本里的英文套路表。

`$A/genre_rules_fixups.json` 是指令级措辞的修正表：迭代产出的规则偶尔会把当时试写那本书的专有设定写进**指令**里（例如要求每本书都去铺垫某个特定法器），那样会把一个人的世界观推进所有人的书。发现这种情况就在这里加一条「原文 → 改写」，重建时自动套用。示例行里的人名不用管——每个规则文件开头都声明了示例中的人名设定只是演示、不要照搬。
