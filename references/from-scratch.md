# 从零开始：从一个想法（或什么都没有）到第一章，再到持续更新

`$SK` = 本 skill 的 `scripts/` 目录，`$A` = `assets/` 目录。所有命令在**用户选定的工作目录**下执行（项目生成在 `./novels/<书名>/`，建议专门建一个文件夹，比如 `~/my-novel`）。

## 第 0 步：环境

确认 `python3`、`pip install openai`、`OPENAI_API_KEY` 就绪，否则先读 `setup.md`。

## 第 1 步：选题材，读模版

```bash
cat $A/templates/INDEX.md                       # 37 个题材 + 成熟度
cat "$A/templates/男频/西方奇幻.md"              # 选定后读这个
```

模版里有：读者预期与核心套路、推荐开局钩子、立项要问清的问题、带权重的质量自检表。**这些是从几百本高分作品里反推出来的，用户不需要自己准备语料。**

用户说不出题材名时，念 `INDEX.md` 里的名字给他挑，或让他描述想写的故事、你来对应到最近的题材。细节见 `genres.md`。

## 第 2 步：问清他手上有多少东西（入口三选一）

这是整条流程里最需要你开口问的地方。**不要假设用户有设定，也不要假设他什么都没有。**

| 入口 | 用户的状态 | 怎么走 |
|---|---|---|
| **A 完全从零** | "我就想写本小说，剧情你定" | 不传 `--seed`，方案全部由模型提 |
| **B 有点思路** | 给了一个点子、一个场景、一个主角，但没成体系 | `--seed "<他说的原话>"` |
| **C 已有设定** | 手上有人物表、世界观、大纲片段 | `--seed-file <文件>`，已定的部分不会被改掉 |

问法：**"你是想自己定一些设定，还是完全交给我来提方案？"** 然后按他的回答走。

入口 B/C 的要点：把用户说的原话（或他的文件）尽量**原样**传进 `--seed`，不要你先替他总结成几个词——摘要会丢掉他真正在意的那一点。他的设定在后面每一步都会被当成不可改动的部分沿用。

入口 A 不等于你什么都不问。至少把这几件事定下来（他说"随便"就你定，但要明确告诉他你定了什么）：目标读者（男频/女频）、打算写多长、有没有绝对不想写的东西。

## 第 3 步：出几个方案让他挑

**大纲阶段永远给多个版本。** 一个方案摆在面前，用户只能说"行"或"不行"；三个摆在一起，他才说得出"我要第 2 个的金手指配第 1 个的开局"——而这句话才是你真正需要的信息。

```bash
# 完全从零
python3 $SK/gen_premise.py pitch --genre 西方奇幻 --variants 3

# 有点思路
python3 $SK/gen_premise.py pitch --genre 西方奇幻 --variants 3 \
    --seed "重生成反派的管家，想保住小姐这条命"

# 已有设定
python3 $SK/gen_premise.py pitch --genre "女频/快穿" --variants 3 --seed-file 我的设定.txt
```

产出 `premises/<题材>_<时间戳>/pitches.md`，每个方案含：书名、一句话卖点、主角与处境、金手指、核心矛盾、开局场景、与同类的差异、前十章节奏、以及"沿用与补充"（说明沿用了用户哪几条、补了哪几条）。

几个方案在**金手指和核心矛盾上必须互不相同**，这是提示词里的硬要求——给三个措辞不同的同一个故事没有意义。

把 `pitches.md` 的内容念给用户（别只甩文件路径），然后：

- 挑中某个 → 第 4 步展开
- 都不满意 → 追加几个，已给过的会被自动避开：
  ```bash
  python3 $SK/gen_premise.py pitch --genre 西方奇幻 --more premises/<目录>
  ```
- 想混搭（"方案 2 的金手指 + 方案 1 的开局"）→ 把他的要求写进 `--seed` 再跑一次 `pitch`，或直接改 `pitches.json` 里那个方案的字段再展开

**为什么分两步**：一次写满三份"大纲 + 第一章"，用户看完要扔掉两份，钱白花。方案摘要便宜，展开才贵。

## 第 4 步：展开成开篇文件

```bash
python3 $SK/gen_premise.py expand --dir premises/<目录> --pick 2
```

产出 `premises/<目录>/variant_2_premise.txt`：完整大纲（核心设定、主角档案含外形与成长弧、感情线、三段环境迁移、反派、前十章大纲）+ 第一章正文，格式就是 `init` 认的那个。

脚本会自检三件事并在有问题时警告：有没有 `【书本名称】`、有没有 40 个 `=` 的分隔线、第一章正文够不够 500 字。**有警告就先人工改，再 init**——这三样任何一个缺了，项目都会建歪。

### 不走脚本：自己手写开篇文件

用户要完全手写（或你和他边聊边写）也行，复制 `$A/premise_template.txt` 填。三条硬要求：

1. 大纲里要有一行 `【书本名称】书名` —— 书名会成为项目目录名。缺了就拿文件所在目录名当书名，几乎总是错的。
2. 大纲和正文之间用**连续 40 个 `=`** 分隔。
3. 正文章节标题写成 `第1章 章节名`（行首是"第"，数字后紧跟"章"，再一个空格）。写成 `### 第1章：标题` 解析不到，分隔线后的全部文字会被并成第 1 章。章节正文要**超过 500 字**才算真章节。

## 第 5 步：立项

```bash
python3 $SK/write_novel.py init --from premises/<目录>/variant_2_premise.txt
```

它会：取书名建 `novels/<书名>/` → 生成 `bible.json`（故事圣经：世界规则、人物档案、总走向）→ 生成第 1 弧（1–30 章）计划 → 把文件里所有超过 500 字的章节存进 `chapters/` 并逐章压缩摘要 → 写 `state.json`。

`--max-chapter N` 只导入到第 N 章（用户已有前 5 章但想从第 3 章重写，就 `--max-chapter 2`）。

**立项后必做**：把 `bible.json` 读给用户听，**先念 `hard_constraints`**（那是"违反即整章作废"的红线：主角的生理限制、金手指的代价与边界、谁已经死了、哪些力量属于后期），再念人物档案和世界规则。这是后面几百章的地基，现在改是免费的。

`init` 自己挑的红线未必是这本书真正的红线——比如主角是哑巴这种设定，漏了它第三章就会开口说话。有问题直接编辑 json，大改就改开篇文件重新 init（会覆盖同名项目）。细节见 `method.md` 的"硬约束"一节。

## 第 6 步：试写 3 章

```bash
python3 $SK/write_novel.py write --project "<书名>" --count 3 --genre 西方奇幻
```

拿给用户看，问具体问题：主角说话的腔调对不对？节奏太赶还是太慢？金手指的呈现方式满意吗？

不对就动这几处（按成本从低到高）：
1. `novels/<书名>/arc_plan.txt` —— 改近 30 章的剧情走向
2. `novels/<书名>/bible.json` —— 改人物性格、世界规则
3. `$A/prompts/<性别>/<题材>.author.txt` —— 给这个题材补规则（重建模版不会覆盖它），见 `genres.md`
4. `--system-prompt <file>` —— 整套替换写作指令底座（见 `corpus.md`）

改完删掉不要的章节**并回退 `state.json` 和 `summaries.jsonl`**（见 `method.md` 的回退步骤），再重写。

## 第 7 步：持续更新

```bash
python3 $SK/write_novel.py status --project "<书名>"
python3 $SK/write_novel.py write  --project "<书名>" --count 10 --genre 西方奇幻
```

只有一个项目时 `--project` 可以省略（自动识别）。

每 10 章自动据摘要刷新故事圣经，每 30 章（一弧）自动生成下一弧计划。**想在弧线交界处同样挑一挑**，就别等它自动生成：

```bash
python3 $SK/write_novel.py new-arc --project "<书名>" --variants 3
# 看 novels/<书名>/arc_candidates/arc<N>_v*.txt，挑定后：
python3 $SK/write_novel.py new-arc --project "<书名>" --use novels/<书名>/arc_candidates/arc3_v2.txt
```

`--variants` 只写候选、不碰 `arc_plan.txt` 和进度，`--use` 才落地。细节见 `method.md`。

写满一定章数想发到平台，见 `publishing.md`。
